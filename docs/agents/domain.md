# Domain docs

## Before exploring

Read root `GLOSSARY.md` if present, then relevant decisions in `docs/adr/`.
Continue silently when either is absent. Domain-modeling skills create
these documents as terms and decisions are resolved.

## Layout

Use one context across the Vestra workspace:

- `GLOSSARY.md`: shared domain vocabulary.
- `docs/adr/`: architecture decision records.

## Vocabulary and decisions

Use glossary terms in issues, proposals, hypotheses and test names.
Reconsider unfamiliar synonyms; note real vocabulary gaps for
`domain-modeling`.

If a proposal contradicts an ADR, identify the decision and explain
why it should be reconsidered.
